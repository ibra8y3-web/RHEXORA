# GitHub public-network acceptance setup

After pushing the repository, configure these repository Variables and Secrets under **Settings → Secrets and variables → Actions**. Set `RHEXORA_PUBLIC_NETWORK_ENABLED=true` when all public services are online to enable the scheduled weekly probe; manual `workflow_dispatch` runs always execute and report missing configuration as a failure.

## Variables (not secrets)

- `RHEXORA_DHT_BOOTSTRAP`: comma-separated `host:47823` endpoints for public DHT seed nodes you operate or trust.
- `RHEXORA_PUBLIC_RELAY_HOST`: public relay DNS name.
- `RHEXORA_PUBLIC_RELAY_PORT`: normally `47825`.
- `RHEXORA_STUN_SERVER` / `RHEXORA_STUN_PORT`: optional STUN host and port.
- `RHEXORA_ICE_STUN`: optional comma-separated STUN URLs; if omitted, the workflow defaults to `stun:stun.l.google.com:19302`.
- `RHEXORA_ICE_TURN_URL`: optional TURN URI, for example `turn:turn.example.net:3478?transport=udp`.

## Secrets

- `RHEXORA_PUBLIC_ICE_INVITE_B64`: base64-encoded JSON of a private worker invite that includes `ice_signal_url` and `ice_room`. Keep the matching worker running for the duration of the scheduled/manual test.
- `RHEXORA_ICE_TURN_SHARED_SECRET`: the same long random coturn REST-auth secret configured as `static-auth-secret` in the private `ops/ice/turnserver.conf`. RHEXORA generates short-lived credentials for each process.

Run **Actions → Public network smoke tests → Run workflow**. The workflow runs in strict mode: configure the public STUN path, every DHT seed and reachable routing neighbor, Relay endpoint, and a private invite that includes ICE and Relay settings; keep the worker online. It fails if a required component is missing or a real end-to-end task fails. TURN shared-secret authentication uses short-lived credentials generated by each RHEXORA process.

The GPU workflow is separate and requires a self-hosted runner labeled `rhexora-gpu`. The independent security audit cannot be produced by CI; see `SECURITY_AUDIT_REQUEST.md`.
